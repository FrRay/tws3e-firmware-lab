# 接下来研究什么

这次研究走通了从官方原包到增益对照的过程。继续推进时，可以沿着下面几条线补充数据和工具。

## 把方法带到其他 vivo / iQOO 耳机

随本地固件 App 提供的教程以 TWS5 之前的产品为使用对象。现有样本已经显示，这个系列里存在 BES 和 QCC 两种封装路线。

拿到新型号后，可以先保存升级请求和文件哈希，查看文件头、项目名、芯片字符串和包内布局，再决定从哪一套解析方法开始。`oviV` 路线可参考 3e 的包头、LZMA 和 CRC；`APPUHDR5` 路线则继续拆分区、文件系统、下载模块和 PS 参数。

工具扩展时，把型号与版本对应的数据布局写成配置，再补原包重建、修改差异和坏包反例。这样积累的是可复用的格式知识，而每款耳机的参数位置也有自己的出处。

## 前馈增益怎样影响听感

0.50 倍刷入后的降噪减弱，为后续对照提供了清晰起点。下一轮关心的是：从 1.00 往上调，哪些频率变得更安静，哪些频率、底噪或佩戴条件发生变化。

记录时可固定一个室内低频噪声源，保持耳塞、佩戴、降噪模式和位置一致，比较原版与一个倍率。把“低频嗡声更小”“背景嘶声增加”“左耳与右耳不同”分别写下来，比笼统的“增强了”更便于继续研究。

参考 SDK 中的赋值接口将这个比例约束在 0～1。3e 目前采用的是修改启动初值的实验路线，接下来会继续追它的运行时写入、合成后的硬件增益和限幅。1.25、1.50 的安装及听感记录也放在这条线上收集。

## 低频滤波如何调整

3e 普通降噪的内置配置中，第一条数字路径使用七节滤波器，原配置函数支持八节。早期已做过追加低频棚形滤波节的离线实验，还检查了外部配置覆盖、采样率和重复加载。

这条路线可以分别改变低频的幅度和相位。下一步需要把控制器响应与耳机的实际残余噪声对应起来，再选择滤波形状和参数。已有离线原型可以用来复核系数格式、复制顺序和寄存器写入。

## 升级与恢复分阶段追踪

完整 OTA 流程包含文件传输、校验、提交、重启和后续安装。3e 应用会先把文件存到暂存区，通过检查后写入启动交接信息，再重启。当前包从应用偏移 `0x10000` 开始，启动程序位于设备前面的区域。

接下来要取得实际启动程序，查清它如何解压、检查镜像和处理失败；签名机制也在这条链上继续定位。安装中断的记录应写明发生阶段，才能区分蓝牙传输重试、提交失败和重启后的程序故障。

现有的 15 秒触控重置是连接排查入口，具体步骤见[操作流程](3e-workflow.md)。固件恢复入口、同版本重刷和双耳异常处理可以分别补充实测记录。

## 怎样提供有用的反馈

提交 Issue 时附上型号、左右耳版本、原包和修改包的哈希、倍率、App 版本或哈希，以及操作步骤。

文件分析可附字节差异和校验 JSON；安装问题附失败阶段、百分比和错误原文；听感比较写清噪声源、佩戴方式、降噪模式及左右耳表现。有测量条件时，再补残余噪声频谱和测试装置。

设备 MAC、序列号、账号与请求授权信息先脱敏。固件来源可以用下载记录、版本和哈希描述，便于其他人核对。
