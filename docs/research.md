# 解包、定位和交叉验证经验

## 先把地址和容器分开

分析对象是原始下载的完整 BIN。外层包头 512 字节，前四字节为 `oviV`。包内包含压缩容器，解压得到 ARM Thumb 镜像。镜像偏移与完整 BIN 偏移不同；本研究采用 `运行地址 = 0x2c010000 + 镜像偏移`，还观察到执行地址别名。

不要把其他型号的 `APPUHDR5` 当作这个格式，也不要把解压镜像直接交给本地固件 App。

| 完整 BIN 的位置 | 已确认的含义 |
|---|---|
| `0x00` | `oviV` 魔数 |
| `0x04` | 压缩载荷长度，小端 uint32 |
| `0x08` | 完整载荷 CRC32 |
| `0x10` | 项目标识字段，当前值 2321 |
| `0x18 / 0x1c` | 观察到的目标偏移字段，本包均为 `0x10000` |
| `0x20 / 0x24` | 解压镜像长度 / CRC32 |
| `0x2e` | CRC 表项数，小端 uint16，原包 18 |
| `0x30` 起 | 每 64 KiB 累计 CRC；最后一项是前面 CRC 的 uint32 累加和 |

原包 `0x70` 恰好是整载荷累计 CRC，`0x74` 是累加和。它们的位置取决于表长，不应给所有格式写死这两个位置。当前编辑器只接受本包，仍按表的结构重算。

## LZMA 与内部 CRC

`0x200` 开始是四个 `FF`，之后每段为“大端 uint32 压缩长度 + LZMA FORMAT_ALONE 数据”。原包共十段，前九段各解压为 192 KiB，末段 87,896 字节。解压镜像长 1,857,368 字节。

镜像内 `CRC32_OF_IMAGE=0x` 后八字符是内部 sanity CRC。计算范围止于数字文本开始的位置，本包数字起点为 `0x1c5700`。外层末尾也有同名文本，但其数值语义没有确认，重打包时保留原文。

经验：

- 每次修改后按“内部 CRC → 压缩 → 载荷 CRC 表及镜像 CRC”重建。
- 尽量保留未变化压缩块的原字节。当前实验只重压第十段，保留 LZMA 属性和解压布局。
- 先做无修改重建。当前工具的 1.00 必须与官方原包逐字节相同。
- 两个包哈希不同不意味着改了多项功能：压缩会让一个参数变化扩散成大量压缩字节差异。应在解压后按字节审计。
- 校验比较同时覆盖未知头字段，不能只核对已经命名的字段。

## ANC 字段是怎样确认的

镜像偏移 `0x1c3e20` 的 float32 是 `1.0`，启动数据复制后对应 RAM `0x20007b14`。单凭数值或字符串无法确定用途，因此又检查了同芯片 SDK 编译对象：

| SDK 符号 | vivo 镜像偏移 | 交叉证据 |
|---|---|---|
| `iir_coef_copy` | `0x3fa30` | 28 字节完全相同 |
| `iir_filter_coef_copy` | `0x3fe2c` | 116 字节完全相同 |
| `anc_set_gain` | `0x4122c` | 除链接重定位外的 152 字节匹配；数据引用对应 `g_ff_adaptive_gain` |
| `anc_set_gain_f32` | `0x41300` | 除重定位外 26 字节匹配；实际跳转到上述整数函数 |

原始指令会把前馈整数增益乘以该浮点值，再转换为整数；反馈测试不受该比例影响。没有把 `512` 或移位 `9` 当成厂家的强度限制：它们参与 Q9 格式转换。

参考 SDK 的 `anc_set_gain2_float` 将赋值限制在 0～1，但该 setter 没有在 vivo 中完整对应，不能据此断言 vivo 会同样限幅。字段含义有符号和指令依据，全部运行时来源和可用上限仍待查。

## 校验分别证明什么

工具读取用户提供的原镜像，执行其中的原始指令，不提交第三方机器码副本。

- `0x12c974`：原始 CRC32 算法，使用已知向量及破坏载荷反例核对。
- `0x1559f0 / 0x155bf4`：两段应用验包函数。模拟提供 Flash/RAM，日志和 IO 回调被截获，其中 CRC 回调为 zlib；这与独立的原始 CRC 指令检查是两层证据。
- `0x4122c`：原始增益设置函数。加载候选的实际启动数据，检查六种输入、重复设置与反馈对照；硬件输出通道设为零，不执行真实音频输出。

反例也重要：曾构造过损坏 LZMA 属性但修复载荷 CRC 的内存样本，两段应用校验仍可接受、解压却失败。因此验包通过不能替代解压、启动或恢复验证。

SDK 的启动复制格式与 vivo 不同：SDK 样本读取 32 字节启动信息，vivo 已追踪路径写入 104 字节；SDK 解压缓冲与 vivo 实际块尺寸也不同。不能把 SDK 启动文件拿来当此耳机的恢复固件。
